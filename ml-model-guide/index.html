ML Models: When to Use Which

Plain-English decision guide — from supervised vs unsupervised down to picking a model and grading it

There's also a third family

Reinforcement learning — model learns by trial and error from rewards (e.g. pricing bots, recommendations that learn from clicks). Semi-supervised — a few labels + lots of unlabeled data. Useful when labeling is expensive.

Supervised Learning Models

Classification Models

Logistic Regression

What: Simple model that outputs a probability (0–100%) for yes/no questions.

Use when: Fast, simple baseline; need to explain to stakeholders; fairly straightforward relationship.

Example: Probability a customer churns this month.

Watch out: Struggles with complex, non-linear patterns.

Decision Tree

What: A flowchart of yes/no questions that leads to an answer.

Use when: Very easy to read and explain; mix of number and category inputs.

Example: Rules like 'no order in 30 days AND no loyalty points → likely to churn'.

Watch out: A single tree overfits (memorizes) easily — use a forest instead.

Random Forest

What: Many decision trees voting together for a more stable answer.

Use when: Want strong accuracy without much tuning; need feature importance; medium tabular data.

Example: Predict churn AND see top drivers: recency, spend drop, complaints.

Watch out: Less interpretable than one tree; bigger and slower.

XGBoost / Gradient Boosting

What: Trees built one after another, each fixing the previous one's mistakes.

Use when: Want top accuracy on tabular data; can spend time tuning; common winner for churn, propensity, fraud.

Example: Your SMS propensity model — XGBoost with SHAP for feature attribution.

Watch out: Needs hyperparameter tuning; requires SHAP for interpretability.

Regression Models

Linear Regression

What: Draws the best-fit line through data to predict a number.

Use when: Predict a continuous number; want a fast, interpretable baseline; relationship is roughly linear.

Watch out: Assumes linear relationship; sensitive to outliers; needs feature scaling.

Ridge / Lasso Regression

What: Linear regression with a penalty that stops it from overcomplicating.

Ridge (L2): Shrinks all coefficients toward zero. Keeps all features.

Lasso (L1): Can set some coefficients exactly to zero — does feature selection automatically.

Use when: Many features, some may be irrelevant; want regularization to prevent overfitting.

Unsupervised Learning Models

K-Means Clustering

What: Groups data points into K clusters by minimizing distance to cluster centers.

Use when: You want to discover customer segments without predefined categories; exploratory analysis.

Example: Segment restaurant buyers into: casual/seasonal, bulk-buyer, premium-consistent.

Watch out: You must choose K; sensitive to scale (normalize features first); assumes spherical clusters.

PCA (Principal Component Analysis)

What: Reduces the number of features while keeping most of the information.

Use when: Have many correlated features; want to visualize high-dimensional data; preprocessing for other models.

Watch out: Loses interpretability — components are linear combinations of original features.

Anomaly Detection

What: Flags unusual data points that don't fit the learned pattern.

Use when: Fraud detection, system failure alerts, unusual account behavior.

Methods: Isolation Forest, One-Class SVM, Z-score thresholds, autoencoder reconstruction error.

Key Concepts

Bias-Variance Tradeoff

Bias: Error from wrong assumptions. High bias = underfitting (model too simple to capture patterns).

Variance: Error from sensitivity to training data. High variance = overfitting (model memorizes training data).

Tradeoff: Increasing complexity reduces bias but increases variance. The sweet spot is where total error is minimized.

Fix high bias: More complex model, add useful features, less regularization.

Fix high variance: More data, simpler model, regularization, cross-validation.

Precision vs Recall — When to Favor Each

Favor Precision when: False alarms are costly. Example: spam filter — don't accidentally block real email.

Favor Recall when: Missing positives is costly. Example: cancer screening — never miss a case.

F1 is the harmonic mean — use when you need balance between the two.

Cross-Validation

k-fold: split data into k parts, train on k-1, test on the rest, rotate. Average the scores.

More reliable than a single train/test split. Helps detect overfitting and tune hyperparameters.

For time-series data: Never use random k-fold — use time-based splits (walk-forward validation) to avoid leakage.

Data Leakage

When information from the future or the answer sneaks into training. Model looks amazing in testing but fails in production.

Causes: Scaling before the split, using a feature that includes the target, temporal data not split properly.

Fix: Split first, then fit transforms only on train data. For time-series: use strict temporal cutoff.

Example: Using 'cancellation date' to predict churn — it already gives away the answer.

DS Concepts Q&A

What is L1 vs L2 regularization?

A penalty that stops the model from getting too complex. L1 (Lasso): can shrink some weights to zero → drops useless features. L2 (Ridge): shrinks weights smoothly toward zero, keeps all features. Rule: Lasso = selection (zeros out). Ridge = shrinks but keeps.

Bagging vs Boosting

Bagging: Train many models in PARALLEL on random data samples, then average/vote. Mainly reduces VARIANCE (overfitting). Example: Random Forest.

Boosting: Train models in SEQUENCE, each fixing the previous one's mistakes. Mainly reduces BIAS (accuracy). Example: XGBoost, AdaBoost.

Remember: Bagging = parallel + vote (fix variance). Boosting = sequential + correct (fix bias).

What is the p-value (in plain English)?

Chance of seeing this result if there were really no effect. Small p-value (<0.05) → result is unlikely to be just luck. It does NOT prove the effect is large or important.

Type I vs Type II error

Type I (false positive): Saying there's an effect when there isn't. Type II (false negative): Missing a real effect. Remember: Type I = crying wolf. Type II = missing the wolf.

How do you handle imbalanced data?

Use the right metric: Precision, Recall, F1, AUC — not accuracy.

Resample: Oversample the rare class (SMOTE) or undersample the common one.

Class weights: Use scale_pos_weight so the model cares more about the rare class.

Threshold: Adjust the decision threshold (not always 0.5).

What is data leakage and how do you prevent it?

When info from the future or the answer sneaks into training data. Model looks amazing in testing but fails in production. Fix: split first, then fit transforms only on train data.

Parametric vs Non-Parametric Models

Parametric: Fixed number of parameters (linear/logistic regression). Faster, simpler.

Non-parametric: Grow with data (KNN, decision trees). More flexible, need more data.
